# miniz compression WAT extraction queue

This queue scopes the smallest WAT work needed to delete:

- `crates/utility/edgerun-encoding/src/compression.rs`
- `crates/utility/edgerun-miniz-oxide`

Do not rebuild miniz as a Rust compatibility surface. The target is compact,
auditable WAT for the useful wire behavior: raw DEFLATE inflate, bounded
inflate, valid raw/zlib/gzip emission, wrapper parsing, and checksum proof
points. Exact miniz compressed bytes and compression ratios are not required for
deletion. Valid format output plus deterministic verification is enough.

Cargo is not the acceptance gate for this queue. The source can be deleted while
callers are still being moved. Each WAT primitive must have:

- a WAT file under `standards/build/wasm/codec-primitives`;
- a smoke runner under `standards/runners`;
- a manifest under `standards/components/manifests/codec-primitives`;
- `memory`, `proto_abi_version == 2`, `proto_standard_id`, explicit status
  codes, and caller-owned buffers.

## Current Rust surface

`crates/utility/edgerun-encoding/src/compression.rs` exposes:

- `deflate_raw_compress(data, level) -> Vec<u8>`
- `deflate_raw_decompress(data) -> Result<Vec<u8>, CompressionError>`
- `deflate_raw_decompress_with_limit(data, limit)`
- `zlib_compress(data, level)`
- `zlib_decompress(data)`
- `gzip_compress(data, level)`
- `gzip_decompress(data)`

`gzip_decompress` owns header scanning and trailer verification. It accepts
gzip method 8, rejects reserved flag bits, skips `FEXTRA`, `FNAME`, `FCOMMENT`,
and `FHCRC`, inflates the deflate member, then checks CRC32 and ISIZE.

`crates/utility/edgerun-miniz-oxide` owns the heavy behavior:

- raw DEFLATE inflate;
- zlib header parsing and Adler32 verification;
- raw DEFLATE compression;
- zlib wrapped compression;
- streaming/status machinery;
- stored, fixed Huffman, and dynamic Huffman blocks.

Known callers from the current scan:

- `crates/edgerun-oci/src/tar_compression.rs`: gzip layer decompress.
- `crates/edgerun-oci/src/registry/tar_push.rs`: gzip layer compress.
- `crates/edgerun-codelyzer/src/bin/apk_api_calls.rs`: ZIP method 8 raw
  inflate with exact uncompressed-size limit.
- `crates/apps/edgerun-tor-bench/src/tor.rs`: direct `miniz_oxide` zlib/gzip
  body inflate.

Existing checksum primitive:

- `encoding-core.wat::crc32(ptr, len) -> u32`
- `encoding-core.wat::adler32(ptr, len) -> u32`
- `encoding-core.wat::adler32_update(seed, ptr, len) -> u32`

## Status codes

Use these status codes unless a primitive needs a narrower documented subset:

- `0`: ok
- `1`: input_short
- `2`: output_short
- `3`: invalid_data
- `4`: checksum_mismatch
- `5`: size_mismatch
- `6`: limit_exceeded
- `7`: unsupported

Packed returns should follow the existing pattern when returning byte counts:
low 32 bits are status, high 32 bits are written or consumed. Multi-field scans
should write little-endian `u32` records.

## Packet 1: gzip member scanner

Create `gzip-member.wat`.

Purpose: replace the gzip header/trailer logic in
`edgerun-encoding/src/compression.rs` and the partial gzip slicing in
`edgerun-tor-bench`.

Exports:

- `gzip_member_scan(ptr, len, out) -> i32`
- `gzip_member_write_header(out_ptr, out_cap) -> i64`
- `gzip_member_write_trailer(crc32, isize, out_ptr, out_cap) -> i64`

`gzip_member_scan` writes this little-endian record:

- `0`: deflate_off
- `4`: deflate_len
- `8`: flags
- `12`: mtime
- `16`: xfl
- `20`: os
- `24`: expected_crc32
- `28`: expected_isize
- `32`: header_len
- `36`: trailer_off

Scope:

- accept ID1/ID2 `1f 8b`, CM `8`;
- reject reserved FLG bits `0xe0`;
- skip `FEXTRA`, `FNAME`, `FCOMMENT`, and `FHCRC`;
- do not validate FHCRC in the first pass because current Rust only skips it;
- require the 8-byte trailer;
- leave DEFLATE and CRC/ISIZE verification to later composition.

Smoke vectors:

- minimal gzip header generated by current wrapper:
  `1f 8b 08 00 00 00 00 00 00 ff ... crc isize`;
- `FEXTRA` with a two-byte XLEN and payload;
- `FNAME` and `FCOMMENT` zero-terminated fields;
- reserved flag rejection;
- truncated extra/name/comment/trailer rejection.

Acceptance:

```bash
node standards/runners/gzip-member-smoke.js
```

## Packet 2: zlib wrapper

Create `zlib-wrapper.wat`.

Purpose: replace miniz zlib header/trailer ownership without bringing along the
streaming Rust state machine.

Exports:

- `zlib_member_scan(ptr, len, out) -> i32`
- `zlib_write_header(level, out_ptr, out_cap) -> i64`
- `zlib_write_trailer(adler32, out_ptr, out_cap) -> i64`

`zlib_member_scan` writes:

- `0`: deflate_off
- `4`: deflate_len
- `8`: cmf
- `12`: flg
- `16`: window_log2
- `20`: flevel
- `24`: fdict
- `28`: expected_adler32

Scope:

- validate compression method 8;
- validate `(CMF * 256 + FLG) % 31 == 0`;
- reject preset dictionary in the first deletion path;
- parse big-endian Adler32 trailer;
- emit default-window zlib headers compatible with levels 0, 1, 6, and 9.

Smoke vectors:

- known zlib `78 01`, `78 5e`, `78 9c`, `78 da` headers;
- invalid method;
- invalid FCHECK;
- FDICT rejection;
- truncated trailer;
- `adler32("Hello, zlib!")` trailer composition with
  `encoding-core.wat::adler32`.

Acceptance:

```bash
node standards/runners/zlib-wrapper-smoke.js
```

## Packet 3: raw DEFLATE stored-block scanner and encoder

Create `deflate-stored.wat`.

Purpose: immediately replace valid compression output for level 0 and provide a
small proof target before Huffman inflate. This is enough to emit valid
raw/zlib/gzip streams even if compression ratios are poor.

Exports:

- `deflate_stored_scan(ptr, len, out) -> i32`
- `deflate_stored_encode(src_ptr, src_len, out_ptr, out_cap) -> i64`

`deflate_stored_scan` should walk stored blocks only and write:

- `0`: block_count
- `4`: payload_total
- `8`: consumed
- `12`: final_seen

Scope:

- read BFINAL/BTYPE;
- reject BTYPE `3`;
- require byte alignment before LEN/NLEN;
- validate `LEN ^ NLEN == 0xffff`;
- support multiple stored blocks up to 65,535 bytes each;
- return `unsupported` if a fixed or dynamic block is seen.

`deflate_stored_encode` emits one or more stored blocks and sets BFINAL on the
last block.

Smoke vectors:

- empty final stored block: `01 00 00 ff ff`;
- `Hello, zlib!` stored block;
- multi-block payload over 65,535 bytes;
- invalid NLEN;
- truncated LEN/NLEN and truncated payload;
- output-short encode.

Acceptance:

```bash
node standards/runners/deflate-stored-smoke.js
```

## Packet 4: raw DEFLATE inflate core

Create `deflate-inflate.wat`.

Purpose: replace `miniz_oxide::inflate::decompress_to_vec`,
`decompress_to_vec_with_limit`, and the raw inflate needed by gzip/zlib/ZIP
callers.

Exports:

- `deflate_inflate_raw(src_ptr, src_len, out_ptr, out_cap, out_limit, out_record) -> i32`
- `deflate_scan_blocks(src_ptr, src_len, out_record) -> i32`

`deflate_inflate_raw` writes:

- `0`: consumed
- `4`: written
- `8`: block_count
- `12`: last_block_type
- `16`: crc32
- `20`: adler32

Scope:

- stored blocks: required first;
- fixed Huffman blocks: required for deletion because miniz tests and common
  compressed HTTP/ZIP data use them;
- dynamic Huffman blocks: required before deleting miniz source entirely;
- sliding window: 32 KiB maximum distance;
- reject distance before output start;
- enforce `out_cap` and `out_limit`;
- update CRC32 and Adler32 over emitted output so wrapper runners can prove
  trailers without re-reading host buffers.

Implementation guidance:

- Keep the canonical Huffman builder local and table bounded.
- Use RFC1951 fixed tables directly, not generated Rust artifacts.
- Dynamic block support must validate HLIT/HDIST/HCLEN, code-length repeat
  opcodes, missing end-of-block, oversubscribed trees, and invalid distance
  symbols.
- Do not implement miniz streaming state, block-boundary resume, alloc growth,
  or Rust error types.

Smoke vectors:

- stored empty and stored `Hello, zlib!`;
- fixed Huffman sample from miniz tests:
  `73 49 4d cb 49 2c 49 55 00 11 00` -> `Deflate late`;
- a short dynamic-Huffman stream generated once and checked in as hex;
- distance copy across prior output;
- invalid BTYPE `3`;
- missing end-of-block;
- bad stored LEN/NLEN;
- output-short and limit-exceeded.

Acceptance:

```bash
node standards/runners/deflate-inflate-smoke.js
```

## Packet 5: wrapper composition runners

Create composition runners only after packets 1 through 4 exist:

- `standards/runners/compression-zlib-composition-smoke.js`
- `standards/runners/compression-gzip-composition-smoke.js`
- `standards/runners/compression-zip-raw-composition-smoke.js`

Purpose: prove deletion-level behavior across primitive boundaries.

Coverage:

- zlib: scan wrapper, raw inflate, compare emitted Adler32 with trailer;
- gzip: scan member, raw inflate, compare emitted CRC32 and ISIZE with trailer;
- ZIP raw: raw inflate with exact uncompressed-size limit;
- compose stored-block encoder with zlib and gzip writers, then scan and inflate
  the result.

Vectors:

- gzip empty payload;
- gzip `hello`;
- gzip with `FEXTRA`, `FNAME`, and `FCOMMENT`;
- zlib `Hello, zlib!`;
- raw ZIP method 8 payload from a tiny file;
- corrupted gzip CRC;
- corrupted gzip ISIZE;
- corrupted zlib Adler32;
- bounded inflate where output exceeds limit.

Acceptance:

```bash
node standards/runners/compression-zlib-composition-smoke.js
node standards/runners/compression-gzip-composition-smoke.js
node standards/runners/compression-zip-raw-composition-smoke.js
```

## Packet 6: optional fixed-Huffman encoder

Create `deflate-fixed-encode.wat` only if stored-block output is too large for a
specific product path.

Purpose: improve compression ratio without keeping miniz. This is not a blocker
for deleting Rust compression source.

Exports:

- `deflate_fixed_literal_encode(src_ptr, src_len, out_ptr, out_cap) -> i64`

Scope:

- emit one final fixed-Huffman block;
- literal-only is acceptable for the first version;
- no LZ77 match search;
- end with EOB.

Smoke vectors:

- `Deflate late`, round-tripped by `deflate-inflate.wat`;
- empty input;
- bytes 0 through 255;
- output-short.

## Deletion order

1. Add `gzip-member.wat` and `zlib-wrapper.wat`.
2. Add `deflate-stored.wat`; prove stored raw, zlib, and gzip output can be
   emitted and round-tripped.
3. Add `deflate-inflate.wat` with stored and fixed Huffman support.
4. Add dynamic Huffman support to `deflate-inflate.wat`.
5. Add wrapper composition runners proving gzip CRC/ISIZE, zlib Adler32, and ZIP
   raw bounded inflate.
6. Delete `crates/utility/edgerun-encoding/src/compression.rs` once its public
   functions have WAT-equivalent adapters or callers have moved directly to WAT.
7. Delete `crates/utility/edgerun-miniz-oxide/src/inflate/*` after raw/zlib/gzip
   decompression callers use WAT and dynamic Huffman smoke vectors pass.
8. Delete `crates/utility/edgerun-miniz-oxide/src/deflate/*` after stored-block
   encode covers raw/zlib/gzip emission. Keep fixed-Huffman encode optional.
9. Remove `edgerun-miniz-oxide` and compression feature references from manifests
   after caller demolition. Cargo is allowed to be broken during the deletion
   branch.

## Deletion blockers that are not WAT blockers

- Exact compressed byte parity with miniz is not required.
- Compression level semantics are not required beyond producing valid output.
  Adapters may ignore `level` or map it to stored/fixed output.
- Streaming Rust status types are not required.
- `block-boundary` resume support is not required.
- Gzip FHCRC validation is not required because current Rust only skips FHCRC.

## Top caller migrations after WAT exists

- OCI gzip layer read:
  `gzip-member.wat` -> `deflate-inflate.wat` -> CRC/ISIZE proof.
- OCI gzip layer write:
  `gzip_member_write_header` -> `deflate_stored_encode` ->
  `gzip_member_write_trailer`.
- Codelyzer ZIP method 8:
  `deflate_inflate_raw(..., out_limit = uncompressed_size)` and require written
  size equals central-directory/local-header size.
- Tor bench zlib/gzip body:
  wrapper scan -> raw inflate; remove direct `miniz_oxide` use.
- Any remaining direct `miniz_oxide::inflate` call:
  route through the same WAT raw/zlib/gzip adapters or delete the feature.
