# Codex JSON-RPC JSON caller routing

Status: in progress.

Target:

- `crates/edgerun-codex/app-protocol/src/jsonrpc_lite.rs`
- `crates/edgerun-codex/app-protocol/src/protocol/common.rs`

The narrow JSON-RPC boundary no longer imports `edgerun-json` or derives
generic JSON traits. It now owns fixed JSON-RPC records and carries dynamic
payload fields as validated raw JSON spans until the owning Codex protocol
record projects them through WAT-backed JSON field scans.

## Fixed field mapping

Top-level JSON-RPC object:

- `jsonrpc`: optional inbound string; if present it must be `"2.0"`. Outbound
  emitters write `"jsonrpc":"2.0"`.
- `id`: string or signed integer only; maps to `RequestId`.
- `method`: string; present on request and notification.
- `params`: optional raw validated JSON span; owned by the method-specific
  protocol record.
- `trace`: optional object with `traceparent` and `tracestate` strings.
- `result`: raw validated JSON span on success response.
- `error`: fixed error object on error response.

Error object:

- `code`: signed integer.
- `message`: string.
- `data`: optional raw validated JSON span.

Message classification:

- `id` + `method` -> request.
- `method` without `id` -> notification.
- `id` + `result` -> success response.
- `id` + `error` -> error response.

## WAT ownership

Current Rust code is a temporary host-side fixed scanner/emitter. The useful
behavior belongs to:

- `json-tape.wat`: validate object structure and locate field spans.
- `json-scalar.wat`: classify and validate strings and signed integers.
- `json-value-core.wat`: bounded raw span kind checks for `params`, `result`,
  and `error.data`.
- `json-emit.wat`: string escaping and object emission.

Do not reintroduce `Value`, `Map`, `ToJson`, `FromJson`, `json!`, or an
`edgerun-json` compatibility crate at this boundary.

## Remaining Codex handoff

`crates/edgerun-codex/app-protocol/src/protocol/common.rs` no longer routes
`TryFrom<JSONRPCRequest>` or `TryFrom<JSONRPCNotification>` through
`edgerun_json::to_value(...).from_json_value(...)`.

The current handoff is deliberately fail-closed:

- Match by the fixed `method` string from `JSONRPCRequest` /
  `JSONRPCNotification`.
- Keep `params` as an optional validated raw JSON span.
- Return `JsonrpcProtocolProjectionError::NotYetProjected` with direction,
  method, expected params type, expected method field set, and raw span length.
- Client-response, server-response, and server-notification generic
  `edgerun_json::to_value` / `from_json_value` helpers in `common.rs` now fail
  closed through `JsonrpcProtocolProjectionError` instead of materializing a
  generic JSON object.
- Return `UnknownMethod` for methods outside the generated protocol table.
- Do not materialize `Value`, `Map`, `ToJson`, `FromJson`, or `json!`.
