# JC3248W535 Board Notes

Source: `https://github.com/NorthernMan54/JC3248W535EN`, commit
`94ffc13bd011e897e82e4097afd272d6932f3cab`.

This note captures the hardware facts needed for native Edgerun bring-up. The
upstream repository is mostly PlatformIO, ESP-IDF, LVGL, Arduino and demo
payloads; the manufacturer PDFs, pinout images, schematics, and board BSP
pin/protocol definitions are summarized here rather than checked in as local
binary attachments.

## Board Identity

- SKU in manufacturer spec: `JC3248W535C_I_Y`
- Module: ESP32-S3-WROOM-1
- CPU: dual-core Tensilica LX7, up to 240 MHz
- Flash: 16 MB
- PSRAM: 8 MB
- Wireless: Wi-Fi plus Bluetooth/BLE
- Supply: 5 V
- Typical power draw: about 150 mA
- Display: 3.5 inch IPS TFT, 320 x 480
- Pixel format: RGB565, 16 bits per pixel
- Touch: capacitive
- Storage: TF card slot

The PlatformIO board file in the source repo names the variant as:

`ESP32-S3 3.5-inch capacitive touch IPS module 8M PSRAM 16M FLASH Arduino LVGL development 320 * 480`

## Display Controller

The display controller used by the BSP is `AXS15231B`.

This is confirmed by both the manufacturer specification PDF and the board BSP:
the PDF lists `AXS15231B` as the driver chip, while `src/esp_bsp.c` installs
the `esp_lcd_new_panel_axs15231b` driver with a board-specific init table. The
cloned board repo does not contain an alternate panel driver path for this
board.

The board drives it over ESP32-S3 SPI2 in QSPI mode:

| Signal | GPIO |
| --- | ---: |
| QSPI CS | 45 |
| QSPI PCLK/SCLK | 47 |
| QSPI DATA0 | 21 |
| QSPI DATA1 | 48 |
| QSPI DATA2 | 40 |
| QSPI DATA3 | 39 |
| QSPI DC | 8 |
| QSPI TE | 38 |
| QSPI backlight PWM | 1 |
| QSPI reset | not connected |

Important BSP defaults:

- SPI host: `SPI2_HOST`
- ESP32-S3 peripheral path: GPSPI. `sdkconfig` enables LCDCAM/I80/RGB support,
  but this board BSP binds the AXS15231B QSPI panel through
  `esp_lcd_new_panel_io_spi`, not the RGB or I80 LCDCAM driver path.
- SPI mode: `3`
- Pixel clock: `40 MHz`
- LCD command bits in QSPI mode: `32`
- LCD parameter bits: `8`
- Transfer queue depth: `10`
- RGB element order: RGB
- Bits per pixel: `16`
- Backlight PWM: LEDC low-speed channel `1`, timer `1`, `5 kHz`, 10-bit duty
- TE interrupt: GPIO 38, negative edge
- TE timing used by demo: `time_Tvdl = 13`, `time_Tvdh = 3`
- The vendor project runs the ESP32-S3 CPU at `160 MHz`, uses 16 MB flash, and
  initializes octal PSRAM at `80 MHz`. These are not required for first display
  smoke tests, but they matter once framebuffer allocation and Wi-Fi are enabled.

For QSPI commands, the vendor driver transforms 8-bit LCD commands into a
32-bit command word:

```text
write command: ((cmd & 0xff) << 8) | (0x02 << 24)
write color:   ((cmd & 0xff) << 8) | (0x32 << 24)
read command:  opcode defined as 0x0b, not used by the display path observed
```

The draw path sets column address with command `0x2A`. In QSPI mode the BSP
does not send a separate row-address command before transferring pixels. Pixel
data uses `0x2C` for transfers beginning at `y = 0` and `0x3C` for continuation
transfers.

The vendor BSP uses a custom initialization sequence from `src/esp_bsp.c`.
Bring-up should start by sending that sequence verbatim before reducing it.
The first commands unlock/configure the panel with `0xBB`, `0xA0`, `0xA2`,
`0xD0`, `0xA3`, `0xC1`, and related vendor registers. The tail sequence is:

```text
0xA4 ...
0xBB 00 00 00 00 00 00 00 00
0x13
0x11, delay 120 ms
0x2C 00 00 00 00
```

The standalone driver file also carries a default sequence ending in `0x29`
display-on and `0x22` all-pixels-off, but the board BSP overrides it. Treat
`src/esp_bsp.c` as the source of truth for this board.

## Touch Controller

Touch is also handled through the `AXS15231B` support code, but over I2C.

| Signal | GPIO |
| --- | ---: |
| I2C bus | I2C0 |
| SCL | 8 |
| SDA | 4 |
| reset | not connected |
| interrupt | not connected |
| I2C address | `0x3B` |
| speed | `400 kHz` |

GPIO 8 is shared in the BSP definitions as LCD `DC` and touch `SCL`. In QSPI
display mode the panel IO config sets LCD `dc_gpio_num = -1`, so GPIO 8 is
effectively available for touch SCL.

The touch read transaction observed in `src/esp_lcd_axs15231b.c` is:

```text
I2C write:
b5 ab a5 5a 00 00 00 08 00 00 00

I2C read:
8 bytes for one touch point
```

The returned one-point record is packed as:

```text
byte 0: gesture
byte 1: point count
byte 2: x high nibble plus event bits
byte 3: x low byte
byte 4: y high nibble
byte 5: y low byte
```

Coordinate decode:

```text
x = ((byte2 & 0x0f) << 8) | byte3
y = ((byte4 & 0x0f) << 8) | byte5
```

The BSP configures a maximum of one touch point.

## Native Bring-Up Order

1. Keep USB Serial/JTAG logging working first.
2. Configure GPIO 1 as backlight PWM and leave duty at 0 until the panel is
   initialized.
3. Initialize SPI2/QSPI pins 45, 47, 21, 48, 40, 39 in mode 3 at a conservative
   clock first. The vendor path uses 40 MHz once stable.
4. Send the board-specific AXS15231B initialization sequence from
   `src/esp_bsp.c`.
5. Turn display on if needed, then enable backlight.
6. Fill a simple solid color rectangle before adding buffering or rotation.
7. Add TE on GPIO 38 after basic writes work.
8. Bring up I2C0 on GPIO 8/4 at 400 kHz and verify touch address `0x3B`.
9. Poll the touch read command and decode single-point coordinates.
